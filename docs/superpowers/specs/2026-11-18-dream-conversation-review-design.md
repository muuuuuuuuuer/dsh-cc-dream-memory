# Dream 怎样用有限预算查到值得记住的事

2026-11-18 · 设计稿 · 适用于 DSH `0.2.2-rc.5` 和当前插件工作树。

**设计选择**　让现有的一个 Dream agent 先看到一小段有上下文的对话，再按具体疑点查原文。插件用本地规则挑材料，模型判断什么值得长期记住。长期记忆继续使用可手改的 Markdown。运行进度复用现有 manifest 和 checkpoint。

## 从一次失败说起

11 月 18 日的一次手动 Dream 有三个候选会话，约 25 秒结束，没有草案。用量为 88,147 token，其中缓存读取 76,928，输出 2,202。按当时的会话边界统计，最大会话约 527 万字符，其中约 520 万来自工具。当前读取逻辑要求连续范围内需审阅的事件读完，长工具结果还要翻页，模型最多 14 轮。这个样本优先指向翻页和进度判定；它无法证明全部失败都出于同一原因。已有现场记录也出现过证据不足。[读取与结算](../../../src/dream-agent.js) · [现场记录](../../../eval/DSH-0.22.1-FIELD.md)

Claude Code 用本地 Markdown 索引和主题文件按需读取，Anthropic 的工程文章给出用定位符延迟加载原文的做法。Hermes 把值得长期保留的内容写进有容量约束的记忆文件。这里借用三者公开说明的做法，下面的选择、预算与验收是本插件的设计。[Claude Code](https://code.claude.com/docs/en/memory) · [Anthropic](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) · [Hermes 源码](https://github.com/NousResearch/hermes-agent/blob/main/tools/memory_tool.py)

## 一次 Dream 怎么走

1. **先选材料，全程在本机。** 沿用项目、会话学习开关和子代理边界。每次只打开少量候选会话，固定本轮最后一个事件序号。优先抽用户纠正、明确选择、前后说法冲突，以及有工具结果支撑的失败后成功。每处连带前因和后续确认，保留说话人。已有 Markdown 先按标题、描述和命中文本选段。手动指定的 `--focus` 排在前面，`--memory-only` 只整理已有页面。过滤插件自己注入的内容，所有摘录沿用现有的敏感内容处理。
2. **给普通对话留一个位置。** 每批从最久未检查的连续范围取一段，即使没有“记住”“以后”之类的词也会轮到。剩余空间才按上面的信号选取；同一件事的重复日志合并成一处。批内允许出现多件事，也可以从另一个会话找反例。本轮冻结范围内按序轮转，新增活动排到下一轮，避免旧内容一直被挤走。
3. **把贵的读取留给需要证明的结论。** 工具结果先只给工具名、可用的退出状态、短错误和事件位置；未知结果标为未知。连续相同调用合并并保留首末位置。模型可以按会话、事件、偏移或局部关键词回读，查看变更前后的原文。例如用户说“只在 Windows 上这样设”，就把例外随原话一起保留；若要记“改后测试通过”，就取最后一次相关测试的结果行。长日志中找不到支持或存在矛盾，可以缩小结论、留待核实或跳过。复用既有逐条依据校验、草稿差异审阅及撤销流程。目录、片段提示和模型自己的概括只用来找东西。
4. **及时收尾。** 看完本批，模型一次交回已审范围、值得保存的改动或“这一段没有新东西”。宿主校验引用和来源版本，原子保存进度与已核验草案。有新发现时进入现有审阅流程，无新发现也是有效结果。一次生成中断或引用不足时，保留上次完整保存的位置。用户在原有 Dream 状态里能分清“有草稿”“已查无新增”“部分完成，因时间或预算暂停”和“来源已变化”，也能看到剩余范围。

## 什么算查过

模型看到工具名称或摘录，仅说明它看过线索。引用原文时记录实际读取的来源、范围及版本。新版进度另存“已审对话范围”，与旧版逐事件完整阅读分开解释。连续范围中每个合格对话段都已展示并得到有效回执，才推进连续游标；超长发言按偏移续读。跳到远处找到的证据只计入该草案，不能据此越过当中的对话。纯工具区间可以按概览结算，保留按源位置复查的能力。状态按实际审过的范围计数，不能因一个空会话而把整轮显示为审完。

首次模型调用前，宿主就在现有运行目录原子保存待审范围、来源指纹和预算预留。中断恢复时先核对范围与记忆文件基线，后续追加的事件留到下次，已审范围被改写则提示重新取证。续跑沿用现有命令和已核验草案。旧版已完成的连续游标可作为起点；旧版未结算的 checkpoint 按其原有约定恢复。原会话仍由 DSH 持有，插件无需复制整份日志。rc.5 默认配置可用会话列表和事件接口；全文索引可关闭。一次冷读可能载入整份会话，同一运行内复用已打开会话，按需取片段，同时限制同时打开的会话数。[DSH 前提](../../dsh-plugin-prereqs/README.md) · [进度状态](../../../src/state.js) · [续跑](../../../src/dream-run.js)

## 怎样控制开销

**首轮试验用整轮 16,000 token、每次执行 45 秒。** 旧版两个成功的实测分别用了 18,881 和 46,070 token，所以直接把旧流程卡在 16,000 有丢掉有效结果的风险。先在隔离配置跑新读取方式，复测同样两个任务，包括默认用 pnpm、staging 仍用 npm 的发布例外。若小预算损害正确性，再用同一批材料单独放宽预算，区分材料遗漏和额度不足。正式默认值由实测决定，保留用户现有更紧的设置。建议首包材料约 2,000 token，给提示、工具定义、后续对话及输出留空间。继续用当前的单次输出上限和轮数保险；模型可以在有余量时连续查几次，也可以第一轮就结束。[两次成功用例](../../../eval/DSH-0.22.1-FIELD.md)

- 每次实际发请求前计算完整输入，包含系统提示、工具定义、先前往返和本次材料，并预留本次最大输出。优先用对应 tokenizer 或供应商用量接口；回退估计需覆盖中文、代码和序列化开销。先缩包；连最小收尾请求也放不下，就在本地保存并暂停。预估值与实际用量分别记录。
- 缓存命中的输入也计入总 token，估算金额时可按供应商的缓存费率折算。费率未知时只展示 token 和已知用量。所有物理请求都占预算，包括重试。超时后用量未知的请求保留预留额；取消后迟到的响应不能发布草案。读取、工具操作和模型调用共用截止时间。
- 接入时先验证 rc.5 的供应商适配层能否关闭隐式重试，或在每次重试前执行预留。严格预算模式只使用满足其中一项的调用路径；无法控制时，在发请求前提示限制。即便能预留 token，实际金额仍以供应商账单为准。
- 续跑沿用同一运行的累计用量。一轮额度耗尽时，已核验的成果仍可按现有费用策略和审阅规则结算；继续调查需显式开启有新额度的运行。自动触发沿用项目冷却周期，同一未完成批次不会因重启自动反复付费。现有用户配置的费用拦截继续优先。[配置](../../../src/config.js) · [请求循环](../../../src/tool-loop.js)

## 怎样决定值得上线

先冻结相同来源和 Markdown 基线，用旧版与新版做配对比较。人工先标出应记的决定、适用条件及原文位置，另标哪些内容应跳过。样本至少包括大段工具噪声中的一条纠正、没有关键词的决定、仅在工具输出中的结果、后续推翻旧结论、无新信息。再测首个请求中断、续跑、缺失用量和来源冲突。使用现有评测入口及隔离运行目录。[评测入口](../../../eval/README.md)

上线前须同时看到三件事：标注的重要事实及例外能被正确找回且能定位到原文；无新增、超时和中断均能给出真实状态，恢复不跳过未审内容；配对样本的整轮 token 中位数下降，并报告耗时中位数、最慢案例、重试和缓存用量。分别统计“查完”和“找到值得采纳的记忆”，避免靠多写草稿提高成功率。真实模型的对照结果出来前，16,000 token 和 45 秒只作起点。

Shared evidence rule (`src/support.js`): word coverage finds candidate evidence,
but a statement is only accepted when negation, quantities/units and conditions
agree with the source — including the object they modify. The online write path,
the Dream verifier and the Wiki build all call `supportsStatement`/`supportConflict`, so `Always answer in
German.` is not authorized by `Never answer in German.`, `90 seconds` is not
confirmed by a `15 seconds` quote, `Deploy only if tests fail.` is not supported
by `Deploy only if tests pass.`, and swapping a read timeout for a write timeout
is rejected even when the units match. Equivalent spellings stay equivalent
(`8KB` = `8 KB`, `15 s` = `15 seconds`). Sentences are split on `.` only when it
is not a decimal point, so `1.5 seconds` survives as one fact.

Title eligibility requires a host-owned ledger entry for the note's current
name, description and body (`src/verification-ledger.js`, `verification.json` in
the scope directory). The body fingerprint ignores the stamp lines, so editing or
renaming invalidates the entry; the host writes the entry after a Dream run whose
transcript verified every current fact on the page — cited or not — and the name
and description it will be listed under. A model cannot mint eligibility by
typing `STATUS: current`, `VERIFIED:`, `USER CONFIRMED:` or by computing
`VERIFIED AGAINST: <hash>` itself — those lines are stripped, and only the ledger
is consulted. Compaction digest and hot set use the same predicate.

`VERIFIED AGAINST` is still written into stamped bodies as a human-readable
trace of which content was verified; it is not the authority.

## Known gaps in this record

- The four scenarios use real stores and real injection/claim code, but a real
  model was not called in this session; no live "new model session" answer was
  recorded. The live checks above are file/injection/search results.
- Real-model Wiki build/query from the prior live change was recorded separately
  (3 pages, 2,282 tokens; `wiki_answer` accepted a cited page/quote). That build
  predates the final claim-ID build code and should be rerun on request.
- `memory_save`/`memory_update` still write ordinary project notes directly with
  an omitted `basis` (backward compatibility). A write that lands on a user or
  feedback page — or whose wording asserts a user requirement — needs an explicit
  `basis: user-explicit` **and** `evidence`, the verbatim user message. The host
  checks that the quote exists in this session's `[user]` blocks *and* that the
  new lines are supported by it; a quote that only proves the user said something
  else still queues the write for review.
- The verification ledger is written by the Dream apply path after the bytes are
  on disk; memory edits made through `memory_save`/`memory_update` change the body
  fingerprint and therefore drop the page out of the hot set until Dream verifies
  it again. Notes verified before this change carry no ledger entry.
- Wiki content lives in `wiki/.generations/<runId>/`; the root holds only
  `GENERATION`, `.builds` and `.generations`. A store resolves the pointer when it
  is constructed, so a reader sees one complete generation through a publish, and
  the pointer flip is the last commit step. Earlier builds (`15 seconds`) remain
  readable while a new one (`25 seconds`) is being written; a failure before the
  flip leaves the previous generation live and the new directory discarded.
  Pruning keeps the current generation plus two, and skips any generation a live
  reader still holds open (`store.close()` releases it).
- Prompt injection resolves the same pointer (`resolveWikiIndexFile`), so a fresh
  session sees the wiki hint even though the root has no `_index.md`.
- The shared support rule is word coverage plus negation/quantity/condition
  agreement. A quantity is compared with the object it modifies (`read timeout
  15 s` is not `write timeout 15 s`), and a conditional sentence has to survive
  whole: `客户同意时才用 YAML` does not follow from `客户和负责人都同意时才用
  YAML`, and `only if` is not `unless`. A `contradicts` verdict needs the quote to
  restate the same fact with a different value, so a write timeout never
  overwrites a read timeout. It is deliberately conservative: a paraphrase that
  changes a number, swaps two objects or drops half a condition is treated as
  unsupported, so the model may need to quote the transcript more literally (and
  Dream may leave more pages unstamped; such writes go to review instead).

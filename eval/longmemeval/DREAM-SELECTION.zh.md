# Dream 在 30 题实验里把时间花在了哪里

2026-11-20。基线为本机 LongMemEval 的 `run-1`。以下统计只读每题的 `build.json`、`checkpoint-before-dream` 和 `checkpoint-after-dream`。每轮只计后者 `.dreams/<runId>/manifest.json` 一次。不同题的记忆库相互隔离。

## 三种计数

| 观察对象 | 基线 | 含义 |
|---|---:|---|
| 最终进入审阅的文件改动 | 1,137 次，其中 1,001 次暂缓 | 同一文件在不同轮次可重复出现 |
| 子代理任务 | 2,138 次，其中 1,084 次提交空改动 | 阅读一场会话会产生模型开销，即使最后没有提案 |
| 按题目和会话 ID 去重的任务 | 1,252 场，来源共 1,462 场 | 886 次任务属于重复送审，210 场没有出现在任务日志中，涉及 21 道题 |

暂缓会保留来源的待审状态。原调度按上次**完成**时间、创建时间排序，暂缓的老会话因而不断回到队首。原评测循环把每个 ready 副本都当作进展，直到待办清空或耗尽轮数。最终覆盖显示 1,212 场完成、250 场待办。完成答题和评分时，C 组仍有部分来源尚未整理。

969 次对 B 已有文件的写入反馈包含 `Unsupported claims`。其中至少 167 次，日志可见的首个未支持片段（至少 13 个字符）在原 B 文件里逐字出现。日志只保存反馈的前 200 个字符，这个计数无法区分删除、改写、标题范围变化等全部原因。它足以说明整页替换把旧内容带进了证据核验的工作量。逐任务的写入反馈和每轮最终暂缓的文件数使用不同分母。

子代理清单共记载输入 180,497,283 token，其中缓存读取 171,414,135，输出 4,366,073。模型用量包含重复调用的上下文，不能直接按未缓存价格换算金额。

## 插件实际在记什么

| 类型 | B 组实际文件数 | 应当留下的内容 |
|---|---:|---|
| `user` | 709 | 会影响后续回答的个人背景、稳定偏好、带时间的生活变化 |
| `project` | 281 | 持续目标、已作决定、约束、截止时间，以及仓库查不到的运行事实 |
| `feedback` | 101 | 用户明确纠正或确认过的工作方式，以及适用条件 |
| `reference` | 0 | 有持续用途的外部资料入口，以及何时要查它 |

四类合计 1,091 个文件。C 组增至 1,163 个。和 B 对照，新增 72 个，另有 56 个同名文件的原始字节发生变化。文件数和字节差别都无法衡量结论质量。实验设置 `userMemory: project`，默认配置则把 user 笔记放在跨项目层，Dream 整理项目层。

| 来自 B 的例子 | 复用价值 |
|---|---|
| 每月留出 50 美元的送礼预算 | 稳定约束，会改变下一次礼物建议。一次购物时浏览过的品牌通常可以省略 |
| 用户在比较两个奶牛品种，选择仍未确定 | 已有笔记足以回答选购背景。购买人、数量和成交日期仍然未知 |
| 改姓后已决定用 Wix 建站，同一页还列出咨询过的邮箱服务商和助手估算的建站工时 | 建站决定值得保留。备选服务商和一次性的回答细节混在同页，会让后续读者难以区分用户决定和助手建议 |

日常写入由主代理和自动抽取器判断价值，项目规则可以覆盖默认指引。普通写入工具另有重复、冲突、来源和秘密检测。语义价值没有通用的硬性分类器。Dream 先在副本里提出改动，再按文件逐条核对新事实、删掉的旧事实和有事实含义的描述。能找到原话只能证明出处。

## 本次改动

- 三个入口共用同一套取舍标准。先判断候选事实会改变今后的哪项回答或行动。明确的长期偏好、状态更新、决定和持续约束优先。询价、假设、助手单方建议、单轮格式要求和已经记清的事实可以直接跳过。简单偏好允许只写一句。
- 暂缓和完成分别记录。自动 Dream 跳过来源无新活动的暂缓会话，出现新活动后可再次选中。手动 Dream 先处理未暂缓的来源，之后仍可重访暂缓项。旧状态文件可继续读取。
- 新增事实和局部纠正可以只提交改动的正文。宿主检查读过的文件版本和待替换段落的唯一性，保留其他段落，并把替换掉的内容记入历史。同一批里后续局部编辑只继承先前已核验且仍受支持的结论。
- 证据保留逐字引文。正文可以精简，只有引用而没有正文的提案无法生成笔记。短小的单事实新笔记直接用正文生成索引描述。对明确的第一人称陈述，核验器接受有限的主语转换。否定、条件、意向和数量仍影响核验。局部纠正的长引文妨碍匹配时，子代理有一次机会在写入前拆开引用。
- 评测分别记录完整审阅过的不同会话数和实际结算数。固定输入全部审阅过一遍后停止。触及轮数上限或连续无进展时，在报告中保留实际覆盖度。

## 验证与局限

**调度。** 通过 LongMemEval 的正常 build 入口回放 5 场会话，每场由确定性测试子代理提出 1 个缺乏证据的改动。两轮分别审了 4 场和 1 场。5 个提案全部暂缓，5 场各送审一次后评测停止，实际结算数为 0。这个检查只验证调度、记录和停止条件。

**已有笔记上的真模型回放。** 选用用户报告中点名的 `2133c1b5` 和 `gpt4_70e84552_abs`，复制每题的原始 B 检查点，回放原始首轮的 4 场会话。表中旧版取自原始运行，新版取最后一轮。两边均用 `deepseek-flash` 和原评测的模拟子代理，没有送入题目、评分或参考答案。

| 两题共 8 场 | 旧版 | 新版 |
|---|---:|---:|
| 提案 / 暂缓 / 应用 | 3 / 2 / 1 | 0 / 0 / 0 |
| 输入 token（含缓存读取） | 402,762 | 369,087 |
| 缓存读取 token | 375,808 | 341,120 |
| 未命中读取缓存的输入 token | 26,954 | 27,967 |
| 输出 token | 8,914 | 4,812 |

新版输出减少 46%，未命中读取缓存的输入略增。原版通过的是一条 Math 215 转班笔记。B 已记录选课冲突，旧 Dream 单独留下了想转入的班级和教授对超额注册的回复。最后一轮新版没有补充这条细节。开发中的前三次配对回放分别提议 1、1、0 个文件，前两次的转班摘要均待人工核验。不能用零提案算出拦截率，也不能把输出 token 的降幅直接当作账单降幅。

**有明确预期的正反例。** 自动抽取与 Dream 分别从相同的发布笔记开始，独立审阅长期交接偏好、发布命令纠正、一次询价和已记录的发布时间。最终模型运行中，两条正例都进入了正式测试笔记，两条反例都没有写入。Dream 把周会书面交接偏好概括成一句，证据保留用户原句。命令更新为 `pnpm release`，仍在周五下午发布，旧值 `make release` 进入历史。自动抽取的偏好正文仍多写了一句应用说明。开发中曾出现有依据的正文被索引描述连带暂缓、两句引用混在一起导致纠正失败的情况，这组例子参与了调试，不能当作留出集。

真实回放和定向例子覆盖的是写入和采纳。原有 30 题的问答评分没有重跑，标准 DSH 子代理也没有在线验收。尚未测得新版的答题增益、拒答变化、总体拦截率或总体费用。
